% Slide 1: Problem Solving Template
\begin{frame}{Systematic Problem-Solving Template}
  How to tackle any unknown problem in an interview:
  \begin{enumerate}
    \item \textbf{Clarify:} Ask questions about constraints ($n$, value limits, sorted status, memory limits).
    \item \textbf{Example:} Dry run a custom, non-trivial test case.
    \item \textbf{Brute Force:} State the obvious solution ($O(N^2)$ or $O(2^N)$), explaining its bottleneck.
    \item \textbf{Optimize:} Apply pattern matching (e.g. "Do I need a window?", "Can a map help?").
    \item \textbf{Code:} Write clean, modular code, stating edge cases.
    \item \textbf{Dry Run:} Trace the code line-by-line with the example.
  \end{enumerate}
\end{frame}

% Slide 2: EM Lens
\begin{frame}{The Engineering Manager's Lens}
  Interviews are a signal of how you will perform as a team member:
  \begin{itemize}
    \item **Tradeoffs:** Be vocal about time vs. space complexity tradeoffs.
    \item **Production-Ready Code:** Favor clean modular helper methods, input validation, and proper typing over dense one-liners.
    \item **Collaboration:** Treat the interviewer as a teammate. Don't go silent for minutes; explain your thought flow continuously.
  \end{itemize}
\end{frame}

% Slide 3: AI Era
\begin{frame}{Redefining the SDLC in the AI Era}
  How AI coding agents (like Gemini, Copilot) change the baseline expectation:
  \begin{itemize}
    \item **Syntax is Cheap:** Being a human compiler or memorizing syntax is no longer the primary value.
    \item **Logic \& System Design is King:** Focus on high-level reasoning, system architecture, identifying constraints, and verifying correctness.
    \item **Coding speed vs. System security:** Writing code quickly is easy; ensuring it is robust, secure, and fits into the existing framework is the real challenge.
  \end{itemize}
\end{frame}
